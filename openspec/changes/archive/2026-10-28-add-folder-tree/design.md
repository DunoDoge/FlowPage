# Design

## Context

现状：文件夹树的数据层、同步与导入导出已落地（D1–D9、D13）——`folder` 表 + `bookmark.folder_id`、`FlowPage/v1/folders/` 独立同步实体、导入逐段建树与导出嵌套重建。UI 侧曾实现独立 FoldersPage（多列层级浏览 + 分段展开 + 批量编辑），但独立页把「浏览流」与「浏览文件夹」拆成两个界面，且从流拖拽到独立页不可达。首版重构删除 FoldersPage 后把树面板叠在 StreamHome 流列表上方，走查反馈它挤压流的可用高度、深树难用；本次把树移到最左侧页面栏（≥1000vp 停靠），窄屏改为左上角按钮打开的左侧抽屉，长按拖拽改归属。动机见 proposal.md。

约束（引用 AGENTS.md，不复制）：RDB 为唯一事实源、无迁移框架（`CREATE TABLE IF NOT EXISTS` + 吞异常 `ALTER`）、同步 LWW + 墓碑、上传竞态靠 rev/updatedAt 回填、ArkTS 严格子集、主 UI 统一 V2 装饰器。

## Goals / Non-Goals

**Goals:**

- 文件夹树为本地与同步的双端事实源；改名/移动只产生单记录同步流量。
- round-trip：浏览器 HTML → 导入 → 导出，层级与文件夹名无损，顺序按 ADD_DATE 近似还原。
- 文件夹浏览、过滤与整理与流同处流笺主页：树常驻最左页面栏（窄屏经左上角按钮抽屉打开），长按拖拽直接改归属。
- 保留已完成的存储/同步/导入导出与批量 API，本次只改 UI 与交互。
- 复用既有机制：软删除 + 回收站、墓碑、LWW、`(parent, name)` 唯一约束（类比 tag 的 `name_key` 唯一索引）。

**Non-Goals:**

- 拖拽排序（同级 `position`、书签顺序）：拖拽只改父子归属，不写任何排序字段。
- 停靠侧栏可调宽或在 ≥1000vp 时折叠（固定 280vp 常驻；只有窄屏提供抽屉开关）。
- 独立文件夹页与多列层级并排浏览（本次删除 FoldersPage）。
- 搜索命中文件夹名（`searchText` 不纳入；见 Open Questions）。
- 标签机制任何行为变更（仅移除导入时的自动打标）。
- 存量数据迁移（开发期，本地清数据、远端旧记录按 schema<3 无文件夹解析）。

## Decisions

### D1: 文件夹表示——`folder` 表 + `parent_id` 树，否决路径字符串与物化 id 路径

`folder(id, parent_id, name, position, created_at, updated_at, rev, dirty, remote_etag, deleted)`，空 `parent_id` 表示根。

- 备选 A（现状路径字符串 `folder_path`）：改名/移动需重写 N 条书签 → N 次同步上传，且 LWW 逐书签裁决会造成「文件夹改了一半」的脑裂；无法表达兄弟顺序。否决。
- 备选 B（物化 id 路径 `id_path`，改名单行但移动需重写子树的 id_path）：把「移动」的代价从零变成子树级重写，且引入路径维护代码；个人规模下查询收益为零。否决。
- 胜出理由：名字只活在一行 → 改名/移动天然单记录同步；LWW 在文件夹记录上一次裁决，消灭脑裂；`position` 列可表达兄弟顺序。

### D2: 书签以 `folder_id` 引用，`folder_path` 删除——否决双字段共存

`bookmark.folder_id TEXT NOT NULL DEFAULT ''`（空串为根），`SQL_BOOKMARK` 移除 `folder_path` 列定义。开发期无迁移负担：既有开发库走「设置页清空本机数据」，另加一条吞异常的 `ALTER TABLE bookmark DROP COLUMN folder_path` 兜底防旧库残留。

- 备选（同时保留 `folder_path` 作缓存）：双事实源，任何文件夹操作都要维护两处一致性，等于把 D1 否决过的重写代价请回来。否决。

### D3: 文件夹为独立同步实体——`FlowPage/v1/folders/` 集合，墓碑目录共用

远端新增 `folders/<id>.json`（`FolderSyncRecord`：`schema, id, parentId, name, position, createdAt, updatedAt, rev, deviceId`）；墓碑沿用 `tombstones/`（按 uuid，书签与文件夹 id 不会冲突）。`SyncEngine.run` 在书签循环外增加结构相同的车载人循环：墓碑和解 → 远端 plan（`SyncPlanner` 原样复用，dirty/etag/updatedAt 语义同构）→ 本地独有补传。`ensureBase` 增加 `folders/` 的 MKCOL。

- 备选 A（文件夹表仅本地缓存、`folder_path` 继续随书签同步）：保留全部 B1 缺陷，只买到树查询，复杂度无回报。否决。
- 备选 B（文件夹打进某个全局 manifest 文件）：单文件高频改写成为同步热点，丢失 per-record etag 增量。否决。

### D4: `SyncRecord` schema 2 → 3，`folderPath` 替换为 `folderId`

`parse` 遇 `schema < 3` 记录按 `folderId = ''`（落根）解析，`carryLocalFields` 的 `record.schema >= 2` 分支随之简化。远端旧 schema 2 文件无需清理，下次本端编辑上传自然升到 3。

- 备选（schema 2 内字段改名）：语义偷换会让双端不同版本解释同一文件，违背版本号本意。否决。

### D5: 删除语义——级联软删除，否决内容上提与非空拒绝

删除文件夹 = 该文件夹及其全部子孙、连同其中书签一并 `deleted=1` 进回收站；彻底删除/过期清理沿既有路径写墓碑（文件夹墓碑 + 书签墓碑，先传墓碑再删远端）。

- 备选 A（成员上提父级，浏览器无此心智且触发 N 书签重写）：否决。
- 备选 B（非空拒绝）：与浏览器行为（Chrome/Firefox 均级联）不一致，多步操作繁琐。否决。
- 回收站恢复：恢复书签时连带恢复其所属文件夹的祖先链（rev+1/dirty 上传，LWW 晚者胜）；回收站界面只列书签行，文件夹链经书签恢复复活（6.2 验收修复，原「逐条恢复、父级悬空」方案未落地且会永久丢失归属）。同父同名被新文件夹占用时，复活文件夹改用去重名（「名 (2)」），归属不丢；文件夹行已被彻底删除（墓碑）时链止步，书签按 D9 悬空容忍。对端恢复的书签记录落地时（upsertFromRemote）同样连带复活链。

### D6: 顺序——文件夹用 `position`，书签用 `createdAt`（来自 ADD_DATE）

导入按文档序给文件夹 `position` 递增赋值、书签 `createdAt` 取 `ADD_DATE`（缺失回退导入时刻）；导出文件夹按 `position`、文件夹内书签按 `createdAt` 排序。新建文件夹 `position` 追加尾端。拖拽只改归属（`bookmark.folder_id` / `folder.parent_id`），不写 `position` 或 `createdAt`，因此不改变同级排序。

- 备选（书签也加文件夹内 `position`）：给书签引入仅在文件夹视图有意义的字段，且每次移动书签都要维护，收益仅是精确还原浏览器手动排序顺序。否决，以 ADD_DATE 近似。

### D7: 同父同名唯一——部分唯一索引，大小写敏感精确匹配

`CREATE UNIQUE INDEX idx_folder_parent_name ON folder(parent_id, name) WHERE deleted = 0`（SQLite 部分索引，经 `executeSql` 下发）。软删除行不占名字，删除后可重建同名。名字匹配大小写敏感（与浏览器一致，区别于 tag 的 `name_key` 小写归一）。

- 备选（含软删行的全局唯一 + 复活时改名）：复活逻辑复杂且用户不可预期。否决。

### D8: 流过滤为直属等值查询——否决子树过滤（用户裁剪）

点击文件夹行的流过滤用 `folder_id = ?` 等值查询，只显示直属书签；子文件夹内容经树中对应子文件夹行下钻到达，每层流精确对应一层文件夹内容。首版为子树过滤（内存树 DFS 收集 id 集、`folder_id IN (...)`），用户裁剪为直属过滤。内存树构建保留：FolderPanel（侧栏树）装载全量 folder 表（个人规模几百行）构建纯函数树，悬空/环防御（D9）在此处收口，级联软删除（D5）、拖拽落点校验（D14）与行计数（仍含全部子孙）继续依赖子树遍历。

- 备选 A（保留子树过滤）：直属与子孙混排，深树时列表冗长、过滤边界不直观。否决（用户裁剪）。
- 备选 B（`WITH RECURSIVE` CTE 下推 SQL，用于剩余子树查询）：功能等价但把防御逻辑埋进 SQL，测试与调试更难。否决。
- 备选 C（物化 id 路径 + `LIKE`）：同 D1 备选 B。否决。

### D9: 悬空与环——树构建纯函数防御

悬空（书签引用的 folder 不在、folder 的 parent 不在）：流不依赖文件夹，书签照常可见；树中根不可达的文件夹子树整体不显示；导出时悬空书签落根。环（双端互移 X↔Y）：构建时检测，断开环上 `updated_at` 较新一条记录的父子边（视为根），并在日志记录。

- 备选（悬空子树挂根显示）：位置错误但可见，用户无法区分「真的在根」与「暂时失联」，且与导出落根叠加会造成 round-trip 假象。否决。

### D10: UI 形态——文件夹树停靠最左页面栏，窄屏抽屉，否决主页内嵌与独立页

- 位置：≥1000vp 把树放进既有最左导航栏（`SideNav`）——品牌与导航项下方、页脚上方；栏宽 240→280vp，不新增列，流列表列与详情列的宽度模型不变。窄屏（<1000vp，含 700–999vp 两栏与手机）不渲染侧栏，`StreamHome` 头部左上角提供文件夹按钮，点击打开从左侧滑入的抽屉（宽 `min(320vp, 84%)`、全高、带遮罩）。抽屉顶部渲染与侧栏同一组主导航项（复用 `NAV_ITEMS`，含流笺，文字与 ☰ 同 20vp 缩进对齐），点击后关闭抽屉并 `openPane`（手机 push / 两栏切 pane）；主页头部不再显示 标签/同步/设置，只剩 ☰（窄屏）与「批量」，宽屏去重后也一致。停靠态与抽屉态渲染同一个 `FolderPanel`，只是容器与尺寸不同。
- 高度与滚动：停靠态树占导航栏剩余高度、内部纵向滚动，不设 40% 上限；抽屉态占满可用高度。树顶部保留根/全部行与根投放区；拖拽悬停树上下边缘时自动滚动。
- 树形态：缩进树（不是多列层级）。根/全部行 + 根的子文件夹 + 递归子节点；每行 = 名称 + 子树书签计数 +「…」，不画展开箭头。树容器左右留 12vp 空白，行背景不贴栏边。点击行主体统一「筛选 + 展开」：任意文件夹行点击把流筛选到该文件夹（直属过滤，D8 修订），有子文件夹的行同时展开、再次点击收起且过滤不清除（修订 14.7 的「有子项只展开」——该形态下混合文件夹的直属书签只能经「…」菜单到达）；「…」→在流中查看保留为等价入口（多选与读屏路径）。收起只影响树内可见内容；过滤态用与侧栏底色可辨的 token（base/dark 成对），不能用与底色相同的 `surface`。
- `FolderPicker` 保持单链单选（选择器语义，选完即走），用于详情编辑、行菜单与批量栏；不参与侧栏树的浏览。
- 状态：`AppState` 保存 `expandedIds`、树滚动位置与抽屉开合（会话内）；窄屏详情往返与宽屏重建都从这里恢复。宽屏无「收起」概念、侧栏常驻；窄屏抽屉默认关闭，用户手动开合只在会话内保留。多选集合（书签/文件夹）同样提升到 `AppState`，因为书签行在中间列、文件夹行在最左列，是两个兄弟组件的状态。
- 过滤联动：任意文件夹行点击设置 `folderFilter`（重复点击同一行不切换清除；清空走根/全部行或流头过滤芯片），父级行同时切换展开/收起。若右侧 pane 不是流（标签/同步/设置），同时 `goPane(Pane.DETAIL)` 把可见的流带回前台；窄屏点叶子行后关闭抽屉让流立即可见，点父级行保持抽屉打开以便继续下钻（流在抽屉后方已更新）。点根/全部清空过滤。
- 行操作：`…` 仍用 `bindPopup` 锚定到按钮；侧栏容器与外层必须 `clip(false)`，否则 280vp 列内的弹出层被裁剪；桌面右键走同一入口。
- 拖拽：系统 `draggable`；投放目标（文件夹行与根投放区）位于侧栏树内，跨列拖拽靠既有 `FolderDragSession` 单例。窄屏拖拽开始若抽屉关闭则自动打开，拖拽期间遮罩只压暗、不拦截指针；投放提交在侧栏统一调用 `FlowRepository.batchMove`（一次 notify），`StreamHome` 不再保留内联面板的 drop 链路。
- 多选：批量入口仍在流列表头部，勾选状态跨列共享，批量栏同时覆盖书签与文件夹（D11）。
- 可达性：抽屉按钮有完整读屏文案；菜单与批量栏经 `FolderPicker` 提供非拖拽路径。
- 备选 A（保留主页内嵌、与流上下堆叠）：本次走查反馈挤压流高度、深树可用性差，且用户明确要求左侧栏。否决，取代原 13.2/13.3 形态。
- 备选 B（在流列左侧新增独立第四列）：1000vp 下 280 + 380 + 详情已无余量，再拆列必须新增断点并压缩详情。否决。
- 备选 C（树做成独立页或全屏抽屉）：离开流，重蹈 FoldersPage。否决。
- 备选 D（宽屏也只用抽屉）：空间足够却要每次点开，文件夹不再是常驻浏览能力。否决。
- 备选 E（树与书签在流中混排）：与筛选、排序、搜索、回收站语义冲突，且流分页只装载 50 条，树无法稳定展示。否决。
- 备选 F（只做拖拽，不做菜单入口）：键盘、读屏与精确操作不可达。否决。

### D11: 主页多选与批量编辑

- 选择集合：`AppState` 保存 `selectionMode` 与 `bookmarkIds` / `folderIds`（分开存放，允许跨类型混合），因为书签行在流列表列、文件夹行在最左侧栏，两个兄弟组件必须共享同一份状态；由标题行「批量」或行勾选进入；行点击保留原行为（书签打开详情、文件夹过滤与展开），勾选为独立点击区。
- 拖拽整组：已选行被长按时，拖拽 payload 为整个集合（D14）；未选中的行只拖自身。
- 批量移动：目标经 `FolderPicker`；书签 `setFolder`、文件夹 `move`；目标是某所选文件夹自身或子孙时该项跳过并提示，其余完成。
- 批量移出一级：统一语义「目标 = 当前父级的父级」（书签父级为 `folderId`、文件夹父级为 `parentId`），已在根的项跳过；不提供「移出到根」的第二语义（拖到根投放区已覆盖）。
- 批量删除：混合选择一次确认，汇总「N 个文件夹连同子树共 M 条笺 + K 条直属书签」；确认后逐项走 `cascadeSoftDelete` / 既有书签软删除，墓碑与回收站语义复用 D5，不新增删除路径。
- Repository 复用 `batchMove` / `batchMoveOut` / `batchDelete`，循环 DAO 后合并单次 `notify()`；拖拽与批量栏走同一批方法。批量栏仍在 `StreamHome`，但操作的是 `AppState` 里的跨列选择集合。
- 刷新裁剪：流重载只裁剪书签选择；文件夹选择按存活树裁剪；退出多选或对象失效后不残留 id。
- 同步代价：批量移动书签产生 N 条书签记录上传（`folder_id` 随书签记录同步，D2 模型固有代价）；移动/删除文件夹仍是单文件夹记录（D1 优势不变）。

### D12: 行级菜单改用「…」锚定面板，长按归拖拽

7.5（`bindContextMenu` 双绑定）与 9.2（`bindContextMenuWithResponse` 单次绑定）两轮实现后，右键/长按 context menu 在真机/模拟器均不弹出；本次不再尝试 context menu。改为：行尾常驻「…」按钮，`bindPopup` 锚定到按钮打开操作面板；桌面右键调用同一 `showActions` 路径。长按不再承担菜单，全部让给拖拽。FoldersPage 两处旧菜单绑定与仅菜单使用的处理函数随页面删除；新建/改名/移动/删除迁到 FolderPanel 的「…」面板。

- 备选（第三次修复 context menu，如 `onContextMenu` / 自绘 Menu 锚定）：平台触发不可控，且已有可靠锚定面板路径。否决。
- 备选（长按弹菜单，菜单里再进入拖拽）：与「长按拖拽」的直觉冲突，多一步且拖拽入口仍依赖不可控手势。否决。
- 备选（只在非多选状态允许拖拽）：单条拖拽不可用，不满足需求。否决。

### D13: 浏览器语义标记保真——folder.kind 列 + FolderSyncRecord schema 2（6.2 round-trip 验收反馈）

6.2 验收发现：导入把带 `PERSONAL_TOOLBAR_FOLDER="true"` 的「书签栏」当普通文件夹（正确，结构无损），但导出（emitFolder）不回写标记；识别该标记的浏览器（Firefox/Edge 系）再导入时把我们的「书签栏」嵌进它自己的书签栏本体，且逐轮 round-trip 复利加深。

- parser：H3 行按正则探测 `PERSONAL_TOOLBAR_FOLDER` / `UNFILED_BOOKMARKS_FOLDER`，仅在顶层（解析栈深 ≤1，容忍缺最外层 DL）记入 `ParsedBookmarks.topMarks`（name→kind，同名首个生效，深层忽略防伪造）。
- 存储：folder 表加 `kind TEXT NOT NULL DEFAULT ''`（'' | 'toolbar' | 'unfiled'），`SQL_FOLDER` 同步加列 + `applySchema` 吞异常 `ALTER`（既有列迁移模式，bookmark 专用 addColumn 旁加 folder 版）；同父同名唯一约束与 kind 无关。
- 导入：`importHtml` 链解析后对 `segments[0]` 命中 topMarks 的文件夹调 `FolderDao.setKind`（幂等：kind 不变则不 bump rev/updatedAt/dirty，重复导入零同步流量）；完全无书签落位的标记文件夹不创建（沿用「仅书签承载路径物化」的既有语义）。
- 同步：`FolderSyncRecord` schema 1→2 加 kind，parse 对旧记录回退 ''；kind 随记录整体参与 LWW（D1 单记录语义不变）。
- 导出：`emitFolder` 按 kind 回写 `PERSONAL_TOOLBAR_FOLDER="true"` / `UNFILED_BOOKMARKS_FOLDER="true"`；kind 只在导入顶层赋值，用户把带类别文件夹移到深层时仍回写（浏览器自行忽略嵌套标记，不做拦截）。
- 备选 A（导出按「书签栏/Bookmarks bar…」名单补标记）：零 schema 改动但语种名单猜测、用户改名即失效。否决。
- 备选 B（导入拍平标记文件夹、子内容升根）：违背 round-trip 结构无损规格，书签栏+其他书签两棵子树并根。否决。

### D14: 拖拽会话与落点校验

- 会话载体：模块级 `FolderDragSession` 单例保存 `bookmarkIds` / `folderIds` / `originRowId` / `active`。`onDragStart` 时若长按行在 `AppState` 的选中集合内则填充整个集合，否则只填该行；`onDrop` 与 `onDragEnd` 清空。会话跨列有效（书签行在流列、文件夹行在侧栏），不承诺跨窗口拖拽。
- 落点：侧栏树内的文件夹行解析为目标 `folderId`，根投放区解析为 `''`。书签只写 `folderId`；文件夹只写 `parentId`，子树随父级自动跟随，不重写成员书签。投放处理由 `FolderPanel` 读取 `FolderDragSession` 完成，不再经 `StreamHome` 中转。
- 校验：拖拽开始前为目标文件夹算一次子树 id 集；目标等于某个被拖文件夹自身或其后代时跳过该项并提示；所有项当前父级已等于目标时整次为无操作，不发通知、不 bump rev。
- 提交：合法项交给 `FlowRepository.batchMove(bookmarkIds, folderIds, target)`，一次 notify；跳过项汇总为「已移动 N 项，跳过 M 项」提示。
- 排序：不写 `position` / `createdAt`；书签仍按 `createdAt`、文件夹仍按 `position`（D6）。
- 视觉与滚动：多选拖拽的预览显示项数；目标行高亮用可辨 token；拖拽悬停树上下边缘时自动滚动。窄屏拖拽开始若抽屉关闭则自动打开；拖拽期间遮罩只压暗、不拦截指针事件，避免遮罩吞掉投放。
- 备选（系统 `UnifiedData` 跨窗口 payload）：当前无跨窗口拖拽需求，序列化与 ArkTS 类型边界成本更高。否决。
- 备选（每个投放行直接写 DAO）：N 次 notify、N 次卡片推送，且中途失败会留下半批状态。否决。
- 备选（自绘 Pan 手势）：与 List 纵向滚动和长按竞争，系统 `draggable` 已提供长按拖拽语义。否决。

### D15: 侧栏状态与刷新反应性

- 状态：`AppState` 保存抽屉开合、`expandedIds`、树滚动位置与流滚动位置；手机详情 pop 回来（NavDestination 重建）时恢复展开与滚动，抽屉保持进入前的开合状态（不强制打开）。宽屏侧栏常驻不卸载，天然保留；不再需要 `detailReturnPane`。宽屏无折叠概念、窄屏抽屉首次默认关闭；用户手动开合只在会话内保留。
- 刷新：`refreshTick` 触发 `folderTree()` 重载；拖拽/批量提交期间挂起重载，提交完成后一次刷新，避免半批状态闪烁。
- 反应性：文件夹行 ForEach 键包含 `id|name|totalCount`（沿用 12.2 修复），计数或改名变化即重建行；书签行沿用 `id|title` 等既有键。不能用 `index-id` 之类与内容无关的键。
- 裁剪：每次重载把 `expandedIds` 裁到存活文件夹，失效的 `folderFilter` 清空并提示；选择集合按 D11 裁剪。
- 备选（组件本地状态）：手机 NavDestination 重建即丢展开与滚动，重蹈 10.2 的复位问题。否决。
- 备选（全量 diff/虚拟树）：个人规模几百文件夹，重建 + 内容键足够，复杂度无回报。否决。

## Risks / Trade-offs

- [SyncEngine 循环复制导致两处漂移] → 抽公共的「单实体类型同步 worker」（书签/文件夹各注入 DAO 回调），ArkTS 下以接口 + 两个实现承载；两处循环的墓碑和解合并为一次扫描。
- [文件夹与书签墓碑乱序到达（文件夹墓碑先到、书签记录后到）] → 墓碑优先：命中墓碑的 id 不再落地，沿用书签同款规则；子树成员书签在本地删除时即写墓碑，不依赖远端顺序。
- [部分唯一索引在部分 RDB 版本不可用] → `applySchema` 下发后吞异常探测，失败则退化为应用层 `SELECT` 查重（个人规模无感）。
- [导入大文件时逐段 find-or-create 的 SQL 往返] → 复用 `insertBatch` 的 tagCache 模式：`Map<"parentId/name", id>` 缓存 + 单事务批处理。
- [树构建防御逻辑复杂] → 纯函数 + ohosTest 单测覆盖悬空、环、空树、深树。
- [schema 3 期间双端开发版本不同步] → 开发期约定：升级后各端「清空本机数据」并同步一次，避免半新半旧解释。
- [长按拖拽与列表纵向滚动竞争] → 用系统 `draggable(true)` 的长按拖拽语义，不自绘 Pan；拖拽响应区限定行主体，真机与模拟器各验证「长按后拖动不触发滚动、短滑仍滚动」。
- [窄屏抽屉关闭时没有投放目标] → 拖拽开始自动打开抽屉；拖拽期间遮罩不拦截指针，树占全高，目标始终可达。
- [深树投放目标在树可视区外] → 树内上下边缘自动滚动；仍不可达时用行「…」菜单或批量栏的 FolderPicker 兜底。
- [侧栏加宽到 280vp 压缩详情区] → ≥1000vp 的最窄组合为 280 + 380 + 340vp，详情仍可读；若实测拥挤，优先回调栏宽或缩进步长，不新增断点。
- [抽屉遮罩拦截拖拽投放] → 拖拽期间遮罩仅做视觉压暗并放行指针事件，`onDragEnd` 后恢复拦截。
- [混合选择中文件夹被删除或移动后残留] → 每次刷新按存活树裁剪文件夹选择，提交前再校验存在性；失效项跳过并提示。
- [批量拖拽 N 条书签产生 N 次同步上传] → D2 模型固有代价，与批量移动一致；不为此改 schema，提示中说明移动条数。
- [ArkUI 拖拽 API 在 API 26 设备/模拟器行为差异] → 只用官方 `draggable` / `onDragStart` / `onDrop` 路径，真机 + 模拟器双验收；拖拽失败时菜单路径仍可用。
- [移除 FoldersPage 丢失多列并排浏览] → 最左栏树 + 流过滤覆盖浏览需求；真实使用反馈不足时另开独立变更评估，不在本次恢复旧页。

## Migration Plan

本次是 UI/交互重构，无数据库、同步或导出格式变更，无数据迁移；回滚只需还原 UI 提交。tasks 13.2/13.3 的「流列表上方堆叠」形态由第 14 节取代。

1. 删除 `FoldersPage.ets`、`Pane.FOLDERS`、`NavigationRail` 文件夹项、`Index` 文件夹路由与 `detailReturnPane` 文件夹返回分支；`AppState` 的文件夹页字段改为抽屉开合、树展开/滚动与跨列选择字段。
2. 新增 `FolderPanel.ets` 双形态：停靠形态嵌入 `SideNav`（导航项下方，栏宽 280vp），抽屉形态由 `Index` 宿主；`StreamHome` 移除内联面板、在头部左上角新增文件夹按钮；保留 `FolderPicker`、`batchMove/batchMoveOut/batchDelete` 与树构建纯函数。
3. 移除 `BookmarkRow` 长按菜单入口，改为「…」+ 拖拽；FolderPanel 行同构。
4. 设备端回归（ohosTest 全量 + 手动走查）；远端与本地数据不受影响。

## Open Questions

- `searchText` 是否纳入文件夹名（实现上需在改名时本地重写成员书签的 `search_text`，不影响同步；纯增益项，可后续独立变更）。
- `ImportOptions.keepFolders` 移除还是反转为「从叶子文件夹派生标签」的显式选项（导入预览 UI 是否值得加这一行）。
- 树的展开状态与抽屉开合是否跨会话持久化（当前只保留会话内；不影响规格与任务）。
- 停靠侧栏是否允许用户调宽或临时收起（当前固定 280vp 且 ≥1000vp 常驻）。
- 拖拽是否需要触觉反馈或长按震动（可后续独立打磨）。
