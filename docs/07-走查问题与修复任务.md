## N1 · 打开一条书签后无法再打开其他书签

### 复现

1. 在手机首页点击任意书签，进入详情。
2. 用系统返回手势（不是页面左上角「返回」）回到列表。
3. 点击另一条书签。

### 实际

第二条书签只出现选中高亮，不进入详情；有时需要杀掉应用重开才恢复。

### 预期

无论用「返回」按钮、系统返回手势还是侧滑返回，之后点击任意书签都应进入对应详情。

### 初步定位

- 当前手机端导航依赖 `Index` 中的 `detailPushed` 布尔值：
  - `closeDetail()` 会把它置为 `false`；
  - 但系统返回手势由 `NavPathStack` 直接 pop，不会调用 `closeDetail()`；
  - `detailPushed` 残留为 `true`，`@Monitor('appState.selectedId')` 和 `openDetail()` 都拒绝再次 push。
- 另外，`selectedId` 未变化时（重复点同一条）不会触发 `@Monitor`，已有 `wasSelected` 兜底，但无法覆盖系统返回后的状态残留。

### 修复方向

1. 不再用布尔值判断是否已 push，改为检查 `NavPathStack` 当前栈顶名称，或监听 `NavDestination` 的 `onShown/onHidden`。
2. 在详情页 `onHidden`/`onBackPressed` 时重置导航状态。
3. `openDetail(id)` 始终保证：若当前不在 detail，则 push；若已在 detail，则更新 `selectedId` 并让详情页响应。
4. 增加回归用例：返回按钮 / 系统返回手势 / 侧滑 / 删除后返回 / 卡片进入后返回，各路径均可继续打开其他书签。

### 验收

- 连续打开 5 条不同书签，每条都能进入正确详情。
- 用系统返回手势返回后仍可继续打开。
- 从卡片、深链、详情页返回后行为一致。

## N2 · 星标按钮右半部分被遮挡

### 复现

列表项右侧的星标按钮，右半边视觉被裁切/点击无响应，尤其在手机窄屏和长标题行。

### 当前实现

- `BookmarkRow` 右侧使用 `Button`，宽度 40vp，高度 44vp。
- 外层 `Row` 左右 padding 20vp。
- 实机布局中星标按钮右边界约在 x=1189（屏幕宽 1256），距屏幕右缘约 20vp。

### 初步定位

- 星标按钮靠近列表/屏幕右缘，可能被 `ListItem` 裁切或与系统侧滑返回热区重叠。
- 按钮自身没有右侧安全边距；长标题换行时行高变化也可能影响点击区域。

### 修复方向

1. 星标按钮宽度改为 32–36vp，外层 `Row` 右侧 padding 增加到 24vp，或给按钮加 `margin({ right: 8 })`。
2. 确认 `List`/`ListItem` 未开启裁切；必要时把星标放进一个带内边距的容器。
3. 点击区域保持 ≥ 44×44vp（可用透明热区扩展，不改变视觉宽度）。
4. 在 320vp、360vp、393vp 宽度下走查。

### 验收

- 星标完整可见，右半部分可点击。
- 点击星标只切换星标，不触发进入详情。
- 长标题两行、短标题一行都不裁切。

## N4 · 坚果云账号认证失败

### 复现

- 地址：`https://dav.jianguoyun.com/dav/`
- 账号：坚果云登录邮箱
- 密码：坚果云「应用密码」
- 结果：提示认证失败，无法同步。

### 当前实现

- `WebDavTransport` 使用 HTTP Basic Auth。
- `test()` 发送 `PROPFIND`，`Depth: 0`，无 XML body。
- `SyncPage` 对 401/403 统一提示「认证失败」。
- HUKS 解密失败时，`SyncConfigStore.load` 会把密码置空并继续，可能表现为 401。

### 可能原因（按优先级）

1. **HUKS 解密失败**：应用升级/重装/清除密钥后，旧密文无法解密，密码变为空；UI 仍显示「已连接」，同步返回 401。
2. **密码类型错误**：使用了坚果云登录密码，而不是「安全 → 应用密码」中生成的密码。
3. **PROPFIND 兼容性**：部分 WebDAV 服务要求标准 XML body、`Content-Type: application/xml; charset=utf-8`、`Depth: 0`；空 body 可能被拒绝。
4. **URL/路径**：`base()` 去除尾部 `/` 后重新拼接；需确认实际请求为 `https://dav.jianguoyun.com/dav/`，而不是缺少或重复路径。
5. **网络/TLS/代理**：当前把网络错误映射为认证失败，提示不准确。

### 修复方向

1. 在 `WebDavTransport` 记录实际请求 URL、方法、状态码（凭据脱敏），先拿到真实 HTTP 状态。
2. 区分 401（凭据错误）、403（权限/路径）、404（路径）、网络错误。
3. `CredentialCipher.decrypt` 失败时**不要静默置空**：标记「凭据需要重新输入」，清空配置或提示重新登录。
4. `PROPFIND` 增加标准 XML body 与 `Content-Type`，兼容坚果云/群晖。
5. 增加「测试连接」按钮，只测试不写入；显示具体 HTTP 状态。
6. 用真实坚果云应用密码复测；必要时用 `curl` 对照：

```
curl -u 邮箱:应用密码 -X PROPFIND -H "Depth: 0" \
  -H "Content-Type: application/xml; charset=utf-8" \
  --data '<?xml version="1.0"?><D:propfind xmlns:D="DAV:"><D:prop><D:resourcetype/></D:prop></D:propfind>' \
  https://dav.jianguoyun.com/dav/
```

### 验收

- 正确应用密码：连接成功，首次上传/下载正常。
- 错误密码：明确提示「账号或应用密码错误」，不出现「网络错误」。
- 重装/重启后：若 HUKS 密钥失效，提示重新输入密码，而不是静默 401。
- 群晖/Alist 至少各验证一种。

## N5 · 服务卡片冷启动可跳详情，热启动只拉起应用

### 复现

1. 添加「今日笺」或「最近」卡片。
2. 杀掉应用，点击卡片 → 能进入对应书签详情。
3. 应用已启动（前台/后台），再点击卡片 → 只把应用拉到前台，停留在原页面，不进入详情。

### 当前实现

- 卡片 `postCardAction` 使用 `action: 'router'`，`abilityName: 'EntryAbility'`，`params.bookmarkId`。
- `EntryAbility.handleWant()` 读取 `bookmarkId` 后调用 `AppState.select(id)`。
- 手机端 `Index` 依赖 `@Monitor('appState.selectedId')` + `detailPushed` 决定是否 push 详情。

### 初步定位

- 冷启动时 `Index.aboutToAppear` 检查 `selectedId` 并 push，所以第一次可用。
- 热启动时：
  - 如果当前已在详情，`detailPushed` 为 `true`，不会再次 push；
  - 如果卡片指向的书签与当前 `selectedId` 相同，`select()` 不改变值，`@Monitor` 不触发；
  - 如果当前在标签/同步/设置页，也没有统一的「回到详情」路由逻辑；
  - `onNewWant` 可能已收到参数，但只更新了状态，没有发起导航。

### 修复方向

1. 在 `AppState` 增加 `routeTick` 或 `pendingBookmarkId`，提供 `openBookmark(id)`：设置 `selectedId` 并**每次自增** `routeTick`。
2. `EntryAbility.handleWant()` 和卡片参数统一调用 `openBookmark(id)`。
3. `Index` 监听 `routeTick`，执行：
   - 清空/回退到根；
   - `pushPathByName('detail', ...)`；
   - 宽屏时切换 `pane = detail`。
4. 不依赖 `selectedId` 是否变化，也不依赖 `detailPushed`。
5. 验证冷启动、后台、前台、当前在详情、当前在设置页五种场景。

### 验收

- 冷启动/热启动点击卡片都进入对应书签详情。
- 点击不同卡片进入不同书签；点击同一卡片也重新定位到详情。
- 从详情返回后，卡片再次点击仍有效。

## N6 · 接续启动时对端卡在显示图标的开始页

### 复现

1. 设备 A 打开某条书签详情。
2. 通过应用接续（自由流转）把应用切换到设备 B。
3. 设备 B 启动流笺，但一直停留在「显示应用图标」的开始页，不进入首页或详情。

### 实际

接续对端卡在启动图标页，应用内容没有出现；需要手动退出/重开。

### 预期

设备 B 在 2 秒内进入接续前的那条书签详情；至少应先进入首页，不应无限停留在开始页。

### 当前实现

- `module.json5`：`EntryAbility` 已配置 `continuable: true`、`launchType: singleton`。
- `EntryAbility.onContinue(wantParam)` 写入 `bookmarkId` 并返回 `AGREE`。
- 对端 `EntryAbility.onCreate` 只调用 `handleWant(want)` 读取参数，随后异步初始化数据库。
- `onWindowStageCreate` 无条件 `windowStage.loadContent('pages/Index')`。
- **未处理 `LaunchReason.CONTINUATION`，也未调用 `restoreWindowStage`。**

### 可能原因（按优先级）

1. **缺少 `restoreWindowStage`**：接续对端没有恢复窗口舞台，系统停留在开始页/启动图标页。
2. **`loadContent` 与接续恢复冲突**：对端可能应先 `restoreWindowStage` 再加载内容；当前无条件加载，时序不确定。
3. **未设置接续状态**：未调用 `setMissionContinueState(ACTIVE)`，系统可能未把目标端视为已激活的接续实例。
4. **接续参数为空或路由未触发**：`onContinue` 依赖 `AppState.shared.selectedId`，若源端状态为空/被回收，参数为空；但这通常应进入首页，而不是卡开始页。
5. **`launchType` 需要核对**：文档要求配置启动模式；当前 `singleton` 是否适配接续需按 API 26 实测。
6. **数据库初始化阻塞/异常**：`Index` 的 `ready` 门禁会让内容延迟显示，但不应停在系统开始页；仍需日志排除。

### 诊断计划

在两端加临时日志（不记录书签内容）：

- 源端 `onContinue`：是否被调用、`selectedId` 是否为空、返回结果。
- 对端 `onCreate`：`launchParam.launchReason`、`launchReasonMessage`、`want.parameters` 是否含 `bookmarkId`。
- 对端 `onWindowStageCreate`：是否被调用、`loadContent` 回调是否成功。
- 对端 `onNewWant`：热接续是否走该路径。
- `Index.aboutToAppear` / `ready`：是否进入首页渲染。

### 修复方向

1. 在对端 `onCreate` 判断 `launchParam.launchReason === AbilityConstant.LaunchReason.CONTINUATION`：
   - 调用 `this.context.restoreWindowStage(new LocalStorage())`；
   - 调用 `this.context.setMissionContinueState(AbilityConstant.ContinueState.ACTIVE)`；
   - 确保随后只加载一次 `pages/Index`。
2. 调整 `onWindowStageCreate` 与接续恢复的顺序，避免开始页被覆盖或内容未加载。
3. 接续参数统一走 `openBookmark(id)`（与 N5 的路由事件一致），不依赖 `selectedId` 是否变化。
4. 源端 `onContinue` 持久化 `bookmarkId` + 滚动位置；为空时回退首页。
5. 增加启动兜底：若 `loadContent` 3 秒内未完成，主动重试或显示可恢复页面，避免无限开始页。
6. 核对 `launchType` 与接续配置，按官方示例在 API 26 上验证。

### 验收

- 手机 → PC、PC → 手机双向接续均能进入对应书签详情。
- 冷启动接续、应用已在前台/后台的接续都正常。
- 连续接续 3 次无开始页卡死。
- 接续参数为空时能正常进入首页，不卡开始页。

## 附二 · 本轮修复记录与验证（2026-10-20）

### N1 · 系统返回后无法继续打开书签

**根因**

- `Index.detailPushed` 是 `NavPathStack` 的手工镜像。系统返回手势直接 pop 栈，不经过 `closeDetail()`，布尔值残留为 `true`。
- `@Monitor('appState.selectedId')` 与 `openDetail()` 都受 `detailPushed` 拦截；点不同书签时又依赖 `selectedId` 变化，状态残留后只剩高亮。

**改动**

- `common/AppState.ets`：新增 `openBookmark(id)`、`routeTick`、`routeId` 与一次性待处理路由；每次打开都自增 `routeTick`。
- `pages/Index.ets`：删除 `detailPushed` 与 `selectedId` 监听；改为监听 `routeTick`，消费后手机端确保栈顶为 detail，必要时 `clear(false)` 再 push；宽屏直接切到 detail。
- `components/DetailContent.ets`：去掉 `@Builder` 的 `bookmark` 值参数，改为读取 `@Local bookmark`，修复详情内切换书签时标题/域名不刷新的问题。

**验证**

- 手机：打开知乎 → 系统返回键回列表 → 打开 InfoQ → 返回 → 依次打开后 3 条，共 5 条不同书签，全部进入正确详情。
- 2in1：列表点击不同条目，右侧标题、域名、标签与正文同步切换。
- 未再出现“只高亮不进入详情”。

### N5 · 卡片热启动只拉起应用

**根因**

- `onNewWant → handleWant → select(id)` 只更新 `selectedId`，不产生导航事件；同 id 时值不变，`@Monitor` 不触发；在标签/同步/设置页也没有统一回详情逻辑。

**改动**

- 卡片参数、深链、接续参数统一走 `AppState.openBookmark(id)`，由 `routeTick` 驱动路由，不再依赖 `selectedId` 是否变化。

**验证**

- 用 `aa start -a EntryAbility -b com.dunodoge.flowpage --ps bookmarkId <id>` 模拟卡片 Want：
  - 冷启动：进入目标详情；
  - 前台在设置页：清除当前栈并进入目标详情；
  - 已在详情、切换到另一 id：标题与正文同时更新；
  - 应用退到后台后：进入目标详情。
- 2in1 在标签页时收到 Want，右侧切回目标详情。

### N6 · 接续对端卡在开始页

**根因**

- 官方生命周期规定：接续启动（冷/热）触发 `onWindowStageRestore()`，不是 `onWindowStageCreate()`。
- 原实现只有 `onWindowStageCreate()`，且未在 `onCreate` 同步调用 `restoreWindowStage(new LocalStorage())`，窗口内容没有加载，系统一直停在启动图标页。
- 同时缺少 `setMissionContinueState(ACTIVE)`，也未声明不使用系统页面栈恢复。

**改动**

- `entryability/EntryAbility.ets`：
  - `onCreate` / `onNewWant` 判断 `LaunchReason.CONTINUATION`：同步 `restoreWindowStage(new LocalStorage())`，并 `setMissionContinueState(ACTIVE)`。
  - 新增 `onWindowStageRestore(windowStage)` 加载 `pages/Index`；`onWindowStageCreate` 与 restore 共用 `contentLoaded` 守卫，避免重复加载。
  - `onContinue` 写入 `bookmarkId`，并设置 `SUPPORT_CONTINUE_PAGE_STACK_KEY=false`（项目使用 Navigation，系统仅自动恢复 Router 栈）。
  - 增加启动原因、restore、接续状态与路由消费日志，不记录书签内容。
- 接续参数复用 N5 的 `openBookmark(id)`；参数为空时保持首页。

**验证**

- 手机、2in1 常规冷启动、热启动、卡片 Want、返回手势均无回归。

### N4 · 坚果云认证失败

- `core/sync/SyncConfigStore.ets`：解密失败或密码为空时标记 `credentialInvalid`，不再静默继续。
- `core/sync/SyncEngine.ets`：凭据无效时抛出 `NO_CREDENTIAL`，不发起 401 请求。
- `pages/SyncPage.ets`：新增“测试连接”按钮；401、403、404、网络错误、凭据失效分别提示；凭据失效时要求重新输入应用密码。

**验证**

- 本地 WebDAV 模拟服务：
  - PROPFIND 收到 `Content-Type: application/xml; charset=utf-8` 与标准 XML body；
