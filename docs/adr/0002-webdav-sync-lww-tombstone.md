# ADR-0002: WebDAV 为主同步通道，ETag 增量 + LWW

- 状态：Accepted
- 日期：2026-10-26（补记：原决策于 2026-10-20 基线，2026-10-21 真机验证坚果云）

## Context（背景）

跨设备同步的候选通道：①自建/托管云服务（需要后端，与 ADR-0001 冲突）；②WebDAV（坚果云、群晖、
Alist 等用户自有存储，标准协议、无服务端组件）；③鸿蒙分布式 KV（`distributedKVStore`，仅同账号
可信组网 + 局域网，跨网络不可用）。WebDAV 覆盖「跨网络、跨品牌」的绝大多数场景；分布式 KV 受组网
约束，只能作增强，降级为 V1.1 规划，不作为主通道依赖。

## Decision（决策）

WebDAV（Basic Auth，支持应用密码）为唯一已启用的同步通道：远端 `FlowPage/v1/` 布局，单条书签一个
JSON 文件，PROPFIND + ETag 做增量对账；合并采用 LWW（`updatedAt` → `rev` → 本机胜），标签取并集，
败方完整快照进冲突表可手动恢复；删除语义依赖墓碑（ADR-0004）。正文快照不上传（ADR-0003）。
分布式 KV 保持 V1.1 规划，Sync 页不展示未实现入口。

## Consequences（后果）

- 用户用自己的云即可跨端，无运营成本；坚果云/群晖/Alist 实测可行。
- 无服务端协调意味着并发编辑只能靠 LWW + 冲突表兜底，字段级合并不自动做（简化策略）。
- WebDAV 服务商实现差异需要容错（仅用标准方法、DELETE 404 视为成功、连接测试分步提示）。
- 凭据必须加密存储（HUKS AES-256-GCM），见 wiki 同步篇。
