# ADR-0004: 软删除 30 天 + 墓碑防复活

- 状态：Accepted
- 日期：2026-10-26（补记：原决策于 2026-10-21 复审收口，同步语义 2026-10-21 走查 N4 后固化）

## Context（背景）

多端 + 增量同步下的删除有两个风险：①用户误删需要可恢复（回收站体验）；②本地物理删除后，远端
`items/{id}.json` 仍在，其他设备（或本机重装）下次同步会把已删书签**复活**。若删除不落任何痕迹，
「不复活」就无法在无服务端的架构里得到保障。

## Decision（决策）

删除分两级：软删除 `deleted=1` 保留 30 天，期间可在回收站恢复；彻底删除（用户清空或 30 天过期清理）
**必须写 `tombstone` 墓碑**，同步顺序为「先 PUT `tombstones/{id}.json` 让其他设备感知，再 DELETE
远端 item」（DELETE 404 视为成功）；下载前先查墓碑，命中即跳过，绝不复活。任何清理路径都不能跳过
`addTombstone`——它是「不复活」的唯一保障。

## Consequences（后果）

- 回收站体验成立；跨端删除语义一致。
- 墓碑文件永久驻留远端（仅 id + 时间，体积可忽略），换取删除语义的可判定性。
- 所有清理代码路径（清空数据、过期清理、purge、远端墓碑采纳）都背负「先墓碑后删除」的硬约束，
  新增清理入口必须遵守（AGENTS.md 已列为代理红线）。
- 墓碑失败（网络错误）时保留本地墓碑等待重试，可能延迟生效。
