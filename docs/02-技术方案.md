# 流笺 FlowPage · 技术方案

- 文档版本：v1.0（待确认）
- 对应 PRD：`docs/01-PRD.md`
- 目标 SDK：HarmonyOS 6.0 / API 26（`targetSdkVersion: 26.0.0`）
- 语言与框架：ArkTS / ArkUI（Stage 模型）
- 设备：phone / tablet / 2in1

---

## 1. 技术选型

| 领域 | 选型 | 理由 |
|---|---|---|
| UI 框架 | ArkUI 声明式 | 原生性能、一多适配、系统组件一致 |
| 状态管理 | 状态管理 V2（`@ComponentV2` / `@Local` / `@Param` / `@ObservedV2` / `@Trace`） | 新工程无历史包袱，细粒度刷新更可控 |
| 路由 | `Navigation` + `NavPathStack` | 支持单栏/分栏/自适应，适合手机到 2in1 |
| 本地数据库 | `@ohos.data.relationalStore`（RDB） | 事务、索引、复杂查询、稳定 |
| 键值配置 | `@ohos.data.preferences` | 轻量设置、同步游标、卡片快照 |
| 网络 | `@ohos.net.http` | WebDAV、元数据抓取、失效检测 |
| 文件 | `@ohos.file.fs` + `DocumentViewPicker` | 导入 HTML、导出、快照文件 |
| 剪贴板 | `PasteButton` 安全控件 + `@ohos.pasteboard` | 点击即授权，避免权限弹窗骚扰 |
| 分享接收 | `ShareExtensionAbility` | 任意 App 分享链接直接收笺 |
| 服务卡片 | Form Kit（`FormExtensionAbility`） | 桌面「今日笺」与快捷收笺 |
| 跨设备 | WebDAV（主）+ `@ohos.data.distributedKVStore`（辅） | 跨网络 + 同账号局域网双通道 |
| 加密 | HUKS + `@ohos.security.cryptoFramework` | 加密 WebDAV 凭据，后续支持 E2EE |
| 测试 | Hypium（`@ohos/hypium`） | 工程自带，覆盖解析/合并/规范化 |

**原则：零第三方运行时依赖。** 解析器、同步引擎、正文提取全部自研，控制包体与供应链风险。

## 4. 数据模型

### 4.1 表结构

```sql
CREATE TABLE IF NOT EXISTS bookmark (
  id              TEXT PRIMARY KEY,
  url             TEXT NOT NULL,
  url_hash        TEXT NOT NULL,
  title           TEXT NOT NULL DEFAULT '',
  description     TEXT NOT NULL DEFAULT '',
  site_name       TEXT NOT NULL DEFAULT '',
  favicon_url     TEXT NOT NULL DEFAULT '',
  cover_url       TEXT NOT NULL DEFAULT '',
  note            TEXT NOT NULL DEFAULT '',
  excerpt         TEXT NOT NULL DEFAULT '',
  snapshot_path   TEXT NOT NULL DEFAULT '',
  snapshot_status INTEGER NOT NULL DEFAULT 0, -- 0 待补全 1 成功 2 失败 3 关闭
  snapshot_at     INTEGER NOT NULL DEFAULT 0,
  search_text     TEXT NOT NULL DEFAULT '',
  source          INTEGER NOT NULL DEFAULT 0, -- 0 手动 1 分享 2 粘贴 3 导入 4 碰一碰 5 内置浏览器
  folder_path     TEXT NOT NULL DEFAULT '',
  read_state      INTEGER NOT NULL DEFAULT 0, -- 0 未读 1 在读 2 已读
  starred         INTEGER NOT NULL DEFAULT 0,
  archived        INTEGER NOT NULL DEFAULT 0,
  deleted         INTEGER NOT NULL DEFAULT 0,

  updated_at      INTEGER NOT NULL,

);

CREATE UNIQUE INDEX IF NOT EXISTS idx_bookmark_url_hash
  ON bookmark(url_hash);
CREATE INDEX IF NOT EXISTS idx_bookmark_stream

  ON bookmark(deleted, read_state, created_at DESC);

  id         TEXT PRIMARY KEY,

);
CREATE UNIQUE INDEX IF NOT EXISTS idx_tag_name_key ON tag(name_key);

CREATE TABLE IF NOT EXISTS bookmark_tag (
  bookmark_id TEXT NOT NULL,
  tag_id      TEXT NOT NULL,
  PRIMARY KEY (bookmark_id, tag_id)
);
CREATE INDEX IF NOT EXISTS idx_bookmark_tag_tag ON bookmark_tag(tag_id);

CREATE TABLE IF NOT EXISTS conflict (
  id          TEXT PRIMARY KEY,

);

  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS tombstone (
  id          TEXT PRIMARY KEY,

  deleted_at  INTEGER NOT NULL,
  attempts    INTEGER NOT NULL DEFAULT 0,
  last_error  TEXT NOT NULL DEFAULT ''
);
```

### 4.2 模型约定

- `id`：UUID v4 字符串；导入时为每条生成，保证多端不撞。
- 时间：毫秒时间戳 `number`；同步比较使用服务端/本机时钟，允许 ±2 分钟漂移。
- `rev`：本地每次写 +1；用于同毫秒冲突的次级比较。
- `url_hash`：规范化 URL 的 SHA-256 前 32 位十六进制。
- `search_text`：小写拼接 `title + description + site_name + url + note + excerpt + tags`，写入时更新。
- 布尔值用 `0/1`，避免 RDB 布尔兼容问题。
- 删除为软删除：`deleted = 1`，30 天后物理清理并写入 `tombstone`（墓碑）。墓碑保存远端文件 ID，下一次同步补发 `DELETE`；`DELETE` 返回 404 视为成功，401/403/网络错误保留墓碑等待重试。

### 4.3 数据库迁移

- `Database.ets` 维护 `schema_version`，启动时按版本顺序执行迁移脚本。
- V1 建表；后续新增字段使用 `ALTER TABLE ... ADD COLUMN`，不做破坏性变更。
- 所有批量写入使用事务；导入每 200 条提交一次，保证进度与内存可控。

## 5. 关键能力实现

### 5.1 分享收笺（ShareExtensionAbility）

**入口配置**：在 `module.json5` 注册 `extensionAbilities`，`type` 为 `share`，`skills` 声明接收 `ohos.want.action.sendData`，并声明 `https` / `http` / `text/plain` 的 `uris`。具体字段以 API 26 官方样例为准，落地时先用最小配置验证分享面板可见性。

**处理流程**：

1. `onCreate` 解析 `Want`：优先 `uri`，其次 `parameters` 中的文本；正则提取第一个 URL。
2. 展示轻量 `InboxSheet`：链接、域名、自动标题（本地快速解析，不等待网络）、标签建议。
3. 用户点击「收下」→ 写入 RDB → `terminateSelfWithResult` 关闭面板。
4. 主应用启动时扫描 `snapshot_status = 0` 的记录，后台补全元数据与快照。

**约束**：

- 分享面板内不发起长耗时网络请求，避免用户等待。
- 无网络时也能保存，仅保存 URL 与域名。
- 面板高度控制在半屏内，键盘弹出时布局自适应。

### 5.2 粘贴收笺（PasteButton）

- 首页搜索框右侧与空状态中各放一个 `PasteButton`，用户点击时系统临时授权读取剪贴板，**不弹权限框**。
- 读取后 `ClipboardService.extractUrl()`：支持纯 URL、带文案的分享文本、含多个 URL 时取第一个合法项。
- 命中后打开 `InboxSheet` 预填；未命中给出轻提示「剪贴板里没有链接」。
- 不申请 `READ_PASTEBOARD` 动态权限，避免每次启动弹窗；仅在安全控件不可用时降级申请。

### 5.3 HTML 书签导入

**格式**：Netscape Bookmark File（Chrome / Edge / Safari / Firefox / 华为浏览器导出）。

**解析器**：手写状态机，不引入 DOM 库。

```
扫描 token：
  <H3>folder</H3>   → pendingFolder = decode(text)
  <DL>              → stack.push(pendingFolder ?? '')
  </DL>             → stack.pop()
  <A HREF="url">t</A> → emit({ url, title: decode(t), folderPath: stack.join('/') })
```

要点：

- 属性可能单引号/双引号、大小写混合、跨行；用容错正则 `/<a\s+[^>]*href\s*=\s*["']([^"']+)["'][^>]*>([\s\S]*?)<\/a>/gi`。
- HTML 实体解码：`&amp; &lt; &gt; &quot; &#39; &#x...;`。
- 文件夹名去空、去重；路径映射为层级标签 `技术/前端`。
- 编码：优先 UTF-8；检测 `charset=gbk/gb2312` 时用 `util.TextDecoder('gbk')`（API 26 实测确认；失败则回退 UTF-8 并提示）。
- 去重：按 `url_hash` 查询已有记录；重复项跳过并计数。
- 写入：事务批量插入，每 200 条一次；导入过程显示 `已处理 / 总数`。
- 结果：成功、跳过、失败三组；失败可复制清单。

**性能目标**：5000 条导入 ≤ 8 秒（2in1），UI 不卡顿（分批 + `await` 让出事件循环）。

### 5.4 元数据抓取

`MetadataService.fetch(url)`：

1. 仅允许 `http` / `https`；拒绝 `file` / `data` / `javascript`。
2. `http.createHttp()`，`GET`，`Accept: text/html`，UA 使用应用标识，`connectTimeout: 8000`，`readTimeout: 8000`，最大读取 512 KB，跟随重定向（≤ 5 次）。
3. 编码判定顺序：`Content-Type charset` → `<meta charset>` → `<meta http-equiv>` → UTF-8。
4. 解析优先级：
   - 标题：`og:title` → `<title>` → `<h1>` → 域名
   - 描述：`og:description` → `meta[name=description]` → 正文首 160 字
   - 封面：`og:image` → `twitter:image`（仅存 URL）
   - 站点名：`og:site_name` → 域名
   - 图标：`link[rel~=icon]` → `/favicon.ico`
5. 失败降级：保留域名与 URL，`snapshot_status = 2`，详情页提供「重试」。
6. 并发限制：最多 3 个任务；同一域名串行，避免被封。

### 5.5 正文快照与阅读模式

**V1.0（纯文本快照）**

- 优先复用元数据请求返回的 HTML，避免二次请求。
- 去脚本/样式/导航/页脚 → 取 `<article>` 或文本密度最高的容器 → 转纯文本（保留段落换行）。
- 上限 200 KB，存 `files/snapshots/{id}.txt`；RDB 只存路径与前 200 字摘要。
- 失败不影响收笺。

**V1.1（内置浏览器 + 阅读模式）**

- `BrowserPage` 使用 `Web` 组件，顶部地址栏与操作条（收笺、阅读、刷新、分享）。
- 阅读模式：`runJavaScript` 注入提取脚本：
  ```js
  (() => {
    const el = document.querySelector('article') ||
      [...document.querySelectorAll('main,div,section')]
        .sort((a,b) => b.innerText.length - a.innerText.length)[0] ||
      document.body;
    return JSON.stringify({ title: document.title, text: el.innerText });
  })()
  ```
- 原生渲染文本，提供字号、行距、深浅色切换；不加载原页面脚本。
- 阅读进度（滚动百分比）写入 `read_at` 与本地 preferences，供接续恢复。

### 5.6 服务卡片

- 两张卡片：`2x2 今日笺`、`2x4 最近三条`。
- `FormExtensionAbility` 与主应用不同进程：主应用在数据变更后把卡片所需的轻量 JSON 写入 `preferences`（`card_snapshot`），卡片读取该快照渲染，避免跨进程 RDB 竞争。
- 刷新：`updateDuration: 30` 分钟 + 主应用变更后 `formProvider.requestFormUpdate`。
- 交互：点击卡片 → `FormLink` 拉起应用并直达详情；「换一笺」通过 `postCardAction` 触发 `message`，卡片本地轮换。
- 空状态：无收藏时展示「去收第一笺」。

### 5.7 WebDAV 同步引擎

#### 5.7.1 远端布局

```
{baseUrl}/FlowPage/v1/
├── items/
│   ├── {bookmarkId}.json
│   └── ...
├── tombstones/          # 已彻底删除的书签 ID（仅 id + 时间，无正文）
│   └── {bookmarkId}.json
└── meta.json            # schema 版本、写入设备、最后同步时间
```

单条一文件，避免整库文件冲突；便于增量与断点。规模上限约 5000 条，超过后切换分片清单（P2）。

#### 5.7.2 记录格式

```json
{
  "schema": 1,
  "id": "uuid",
  "url": "https://example.com/a",
  "urlHash": "…",
  "title": "标题",
  "description": "摘要",
  "siteName": "站点",
  "faviconUrl": "…",
  "coverUrl": "…",
  "tags": ["技术/前端"],
  "note": "备注",
  "excerpt": "摘录",
  "snapshotText": "正文纯文本或空",
  "createdAt": 1730000000000,
  "updatedAt": 1730000000000,
  "readAt": 0,
  "readState": 0,
  "starred": false,
  "archived": false,
  "deleted": false,
  "rev": 3,
  "deviceId": "…"
}
```

#### 5.7.3 同步算法

```
sync():
  1. 连接测试：PROPFIND baseUrl，校验 207/200 与认证
  2. 确保目录：MKCOL FlowPage / v1 / items（已存在则忽略 405）
  3. PROPFIND items/ Depth:1 → 得到 [{href, etag, lastModified}]
  4. 远端集合 R，本地映射 L（id → remote_etag）
  5. 待下载 D = { r ∈ R | L[r.id] 不存在 或 L[r.id].etag ≠ r.etag }
  6. 待上传 U = { l ∈ L | l.dirty } ∪ { l ∈ L | l.id ∉ R }
  7. for r in D: GET → 解析 → mergeRemote(local, remote)
  8. for l in U: PUT items/{id}.json
       header If-Match: 本地记录的 etag（新文件用 If-None-Match: *）
       412 → 重新 GET → merge → 重试（最多 3 次）
  9. 远端墓碑 R_t = PROPFIND tombstones/；命中 id：删除本地同 id 书签、清理残留 item，并阻止下载
  10. 本地墓碑 T：先 PUT tombstones/{id}.json（让其他设备感知删除），再 DELETE items/{id}.json；
      两步成功（DELETE 404 视为成功）后清除本地墓碑，失败保留重试
  11. 下载前检查墓碑：命中则跳过下载，绝不复活
  12. 上传成功后仅在 rev + updatedAt 未变化时回填 ETag 并清 dirty
  13. 更新 sync_state.lastSyncAt / lastError
```

#### 5.7.4 合并策略

- 主键 `id`；`url_hash` 冲突（不同 id 同 URL）→ 保留较早创建者，另一条合并标签与备注后软删除。
- 双方都有修改：比较 `updatedAt`，较大者胜；相同则 `rev` 大者胜；再相同则本机胜。
- 败方完整 JSON 写入 `conflict` 表，同步中心可见，可「恢复此版本」。
- 删除优先：任一端 `deleted = true` 且 `updatedAt` 更新 → 删除；否则保留。
- 标签取并集（非冲突字段可自动合并），备注/标题/摘要走 LWW。

#### 5.7.5 触发与容错

- 手动「立即同步」；应用回前台且距上次 > 5 分钟；本地写入后 10 秒防抖；网络恢复。
- 指数退避：1s / 4s / 16s，最多 3 次；401/403 不重试，提示检查凭据。
- 同步锁：`sync_state.syncing`，避免并发任务。
- 超时：连接 10s，读写 30s；单文件 ≤ 1 MB。
- 仅 HTTPS；HTTP 明确警告（凭据明文风险）。

#### 5.7.6 凭据安全

- **当前实现**：HUKS AES-256-GCM 加密后写入 `preferences` 的单一 `webdav_config` JSON；密钥别名 `flowpage_sync_credential_key`，解密仅在同步时于内存进行。
- 支持应用密码（坚果云需使用应用密码）。
- 登出时清除凭据与 `remote_etag`，不删除本地数据。

### 5.8 分布式数据通道

- **当前状态**：通道设计保留，批次 B 未启用；Sync 页显示「下一阶段接入」。计划使用 `@ohos.data.distributedKVStore`，库名 `flowpage_sync`，键 `b:{id}`，值与 WebDAV 记录格式一致。
- 权限：`ohos.permission.DISTRIBUTED_DATASYNC`（用户授权）。
- 设备发现：`@ohos.distributedDeviceManager` 获取可信设备列表；仅在 `deviceManager` 可用且同账号组网时启用。
- 同步：`sync(deviceIds, PUSH_PULL)`，监听 `dataChange` 做增量合并，复用 `MergePolicy`。
- 限制：仅同应用、同账号、可信组网；不传快照正文（体积大），只同步元数据与标签。
- 冲突：与 WebDAV 相同的 LWW + 冲突表。

### 5.9 碰一碰 / 隔空传送 / App Linking

- **发送**：`systemShare` 分享 `https://{domain}/b/{id}` 链接，配合 Share Kit 的碰一碰/隔空传送能力。
- **接收**：`module.json5` 声明 `ohos.want.action.viewData` + `https` 域名 + `domainVerify: true`；同时注册自定义 scheme `flowpage://bookmark/{id}` 作为无域名兜底。
- **当前实现**：自定义 scheme `flowpage://bookmark/{id}` 已注册并可显式拉起详情；分享面板已接入 Share Kit。HTTPS App Linking 仍需真实域名与 `/.well-known/applinking.json`，作为发布前配置项。
- 碰一碰需要两台真机；单设备环境仅验证分享面板与链接解析。

### 5.10 应用接续

- 已在 `module.json5` 设置 `continuable: true` 与 `launchType: singleton`，并实现 `onContinue`。
- `onContinue` 保存：`bookmarkId`、滚动位置、阅读模式、字号。
- 目标端 `onCreate` / `onNewWant` 读取 `want.parameters` 恢复详情页与滚动。
- 数据量 < 100 KB，直接走 `want.param`，不传文件。
- 无第二设备时，仅验证参数序列化与恢复逻辑（单元测试）。

### 5.11 搜索

- 查询：`WHERE deleted = 0 AND search_text LIKE ?`，参数 `%kw%`，转义 `%` `_` `\`。
- 排序：`starred DESC, created_at DESC`；可按标签、域名、已读状态叠加过滤。
- 结果高亮：在 UI 层对 `title` / `description` 做子串定位，使用 `Span` 分段着色。
- 10,000 条以内目标 < 100 ms；超出后引入分页与索引优化。

## 6. 权限与隐私

### 6.1 权限清单

| 权限 | 级别 | 用途 | 申请时机 |
|---|---|---|---|
| `ohos.permission.INTERNET` | system_grant | 元数据、WebDAV、内置浏览器 | 安装时 |
| `ohos.permission.GET_NETWORK_INFO` | system_grant | 网络状态与同步触发 | 安装时 |
| `ohos.permission.DISTRIBUTED_DATASYNC` | user_grant | 分布式同步 | 用户开启该通道时 |
| `ohos.permission.READ_PASTEBOARD` | user_grant | 安全控件不可用时的降级 | 仅降级场景 |

不申请：通讯录、位置、相机、麦克风、相册、后台持续运行。

### 6.2 隐私设计

- 默认纯本地；未开启同步时无任何数据出端。
- 不接入统计、广告、推送 SDK。
- 元数据抓取仅请求用户主动收藏的 URL；不携带设备标识。
- WebDAV 凭据加密存储；日志中脱敏 URL 查询参数与账号。
- 提供「导出全部数据」与「删除全部数据」，导出格式开放（JSON + Netscape HTML）。
- 隐私说明以应用内页面呈现，首次启动不弹隐私弹窗（仅系统权限弹窗）。

## 7. 性能与质量预算

| 指标 | 目标 |
|---|---|
| 冷启动到首页可交互 | ≤ 800 ms（2in1） |
| 首页 1000 条滚动 | 稳定 60 fps，使用 `LazyForEach` |
| 单条收笺（本地写入） | ≤ 100 ms |
| 元数据抓取 | P90 ≤ 3 s，超时 8 s |
| 5000 条 HTML 导入 | ≤ 8 s |
| 搜索 10,000 条 | ≤ 100 ms |
| 同步 1000 条增量 | ≤ 30 s（良好网络） |
| 安装包 | ≤ 20 MB |
| 崩溃率 | < 0.1% |

**降级策略**：

- 网络失败 → 本地可用，标记待补全。
- WebDAV 不可用 → 提示并保留本地变更，下次重试。
- 分布式不可用 → 自动隐藏入口，不阻塞主流程。
- 卡片刷新失败 → 展示上次快照。

## 9. 技术风险与对策

| 风险 | 对策 |
|---|---|
| API 26 分享扩展/接续字段与文档示例有差异 | 先做最小可用 Demo 验证，再扩展；保留 `flowpage://` 兜底 |
| `TextDecoder` 对 GBK 支持不确定 | 实测；失败时降级 UTF-8 并提示用户转码 |
| WebDAV 服务商差异（坚果云/群晖/Alist） | 只用标准方法；连接测试分步提示；提供请求日志导出 |
| 2in1 上 Web 组件与窗口行为差异 | 单独适配窗口尺寸变化与键鼠事件 |
| 无第二设备导致跨端未验证 | 明确标注「未验证」，提供自测脚本与模拟数据 |
| 同步文件数过多导致 PROPFIND 慢 | 5000 条后切换分片清单 |
| 网页正文提取质量 | 先纯文本 + 手动摘录；阅读模式作为增强，不承诺完美 |
